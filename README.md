# Mark's Marketplace

Standalone Test 3 app: browse photo listings, filter categories, search titles, publish listings, and save private buyer messages. Built with Next.js, React, TypeScript, Tailwind CSS, shadcn/ui, and Supabase.

## Run locally

Use Node.js 24. Run `npm ci`, copy `.env.example` to `.env.local`, and enter the marketplace project's public URL and publishable key. Run `npm run dev` and open http://127.0.0.1:3000.

Routes: `/` for browsing, `/new` for publishing, and `/listings/[id]` for listing details and Message Seller.

## Database

Run `supabase/marketplace.sql` once in a new Supabase project's SQL Editor. It creates listings, private buyer messages, indexes, RLS policies, and the public `listing-images` Storage bucket. JPEG, PNG, and WebP files are limited to 5 MB. Never apply this schema to a project containing existing tables with these names.

Listings, seller emails, and listing photos are public. Visitors can insert validated listings and messages, but cannot edit/delete listings, overwrite/delete photos, or read buyer messages. IDs and timestamps are generated by the database. Prices are stored as integer USD cents.

No login, checkout, seller inbox, or email notifications are included. Project administrators can review buyer messages in Supabase. A saved message does not send an email; the UI makes this clear. Anonymous submissions have no app-level rate limit or moderation, and abandoned uploads require administrator cleanup.

## Checks

```powershell
npm test
npm run typecheck
npm run build
npm run test:marketplace
```

The live smoke check requires `.env.local`. It uploads the public profile portrait as a labelled demo image, creates a demo listing and private test message, and verifies persistence, filters, validation, and denied access/mutation. It leaves diagnostic records for administrator review and prints their listing ID. Check message persistence separately as an administrator, since the public client cannot read messages.

Build and development use Next.js's supported webpack option because the CSS worker crashes with Turbopack on this Windows environment. Package versions and the lockfile are pinned.

## Deployment

Use this repository's own Vercel project. Add `NEXT_PUBLIC_MARKETPLACE_SUPABASE_URL` and `NEXT_PUBLIC_MARKETPLACE_SUPABASE_PUBLISHABLE_KEY` before building. Never place a service-role/secret key in public environment variables. `.env.local` and `.vercel` are ignored.

Production verification and screenshots are recorded in `TESTING.md`. This app has no dependency on the wall repository, database, or Vercel project. No application is automatically submitted.
